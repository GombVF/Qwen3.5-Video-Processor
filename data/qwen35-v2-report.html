GAP 1 Ambiguous Objects & Unsupported Specificity

The v1 prompt allowed the model to name specific substances, brands, and exercise variants without visual evidence. The v2 observation prompt adds explicit Evidence-Grounding Rules and Forbidden Inferences sections that require neutral, evidence-bounded wording.

What changed

  • New rule: when identity or material is ambiguous, describe observable shape, color, position, and movement instead of naming a specific substance or object.
  • Forbidden: exact substances ("salt"), brand names, precise exercise variants ("bench press"), emotions, intentions, and audio.
  • Positive examples enforce neutral descriptions: "a white powder" not "salt", "a lower-body exercise with a barbell" not "squats with 100kg".
  • Negative examples show what the model must not produce: inferred emotions, inferred purpose, audio inference, unsupported brand/location.
  • Global overview prompt gets matching grounding rules and the principle "prefer omission over invented completeness."

GAP 2 Inconsistent Action/Scene/Appearance Classification

Without explicit definitions, the model would inconsistently classify the same visual event as different types across windows. The v2 prompt adds a strict taxonomy with definitions and classification examples.

Taxonomy

TypeDefinitionExample
action Observable movement, manipulation, posture transition, or meaningful visual change "A pigeon walks along a ledge"
scene Visible setting, composition, environmental state, or static contextual view "A dark hallway with dim lighting"
appearance Stable visible attribute: clothing, accessories, physical features "A person wearing headphones"

Key disambiguation: "putting on headphones" is an action (manipulation), while "wearing headphones" is appearance (stable attribute). Camera panning across a landscape with no subject action is scene.

GAP 3 Token-Aware Deduplication

The Qwen 2.5 v5 baseline's deduplication was stronger than v1's character-only similarity. The consolidator now uses a dual-metric approach with window-distance-aware thresholds.

Dedup algorithm

  • Character similarity: SequenceMatcher.ratio() on NFKC-normalized, casefolded text.
  • Word similarity: Jaccard index on word token sets. Catches semantically identical sentences that differ by word order.
  • Combined score: max(char_sim, word_sim). Either metric alone can trigger deduplication.
  • Adjacent windows only (distance=1): comparisons use adjacent_threshold=0.78. Same-window pairs (distance=0) are skipped because the model handles intra-window dedup. Non-adjacent pairs (distance>1) are preserved to keep genuinely repeated actions.

GAP 4 OCR Fragment Removal

OCR extraction across frame batches produced fragmented text: "SUBSCRIBE" appearing as a separate entry alongside "SUBSCRIBE NOW" from an adjacent frame. The consolidator now removes fragments that are contiguous substrings of longer texts from nearby frames.

Fragment detection

  • For each OCR text, check if its normalized form is a contiguous substring of any longer text from a frame within the fragment_neighborhood distance (default: 3 frames).
  • Fragments shorter than 4 characters are kept to avoid false positives on abbreviations.
  • Distant frames (beyond neighborhood) are not compared, preserving genuinely independent text appearances.
  • No reconstruction: fragments are removed, never combined. Text that doesn't exist verbatim in model output is never created.

Pipeline wiring

The OCR pass now tracks text_frame_sequences: list[int] alongside visible_texts. Each text entry carries the global frame sequence number it was extracted from, enabling distance-aware fragment comparison.

GAP 5 Independent Pass Degradation

In v1, a failure in the global overview or OCR pass could abort the entire pipeline. Each pass now has independent error boundaries with granular status tracking.

Degradation behavior

All windowsPipeline raises RuntimeError—

The PassStatus enum (complete / partial / failed / skipped) is reported per pass in the metrics response, giving callers fine-grained degradation information.

Performance Track: Kernel Evaluation

Qwen 3.5 uses a hybrid attention architecture: 24 Gated DeltaNet layers for linear attention and 8 full attention layers. Two optional kernel packages can accelerate these layers.

Evaluation results

PackageVersionInstalledActiveVerdict
flash-linear-attention 0.5.2 Yes No Blocked by triton
causal_conv1d 1.7.0 No No CUDA-only

flash-linear-attention

The package installs as pure Python (fla-core==0.5.2 + einops==0.8.2), but its operator implementations (fla.ops.gated_delta_rule) require triton, which is Linux-only. On Windows, import fla succeeds but from fla.ops.gated_delta_rule import chunk_gated_delta_rule fails with ModuleNotFoundError: No module named 'triton'.

Transformers' dispatch mechanism (use_kernel_func_from_hub_with_fallback) catches this exception and falls back to the built-in PyTorch reference implementation. The fallback is functionally correct but Transformers' own documentation notes the gap is "more than an order of magnitude on an H100."

causal_conv1d

Building causal_conv1d==1.7.0 from source fails with NameError: name 'bare_metal_version' is not defined. The package requires CUDA bare-metal headers and is fundamentally incompatible with ROCm.

Dispatch verification

# Both functions resolve to the Transformers PyTorch reference path:
chunk_gated_delta_rule.__module__
  → "transformers.models.qwen3_5.modeling_qwen3_5"
causal_conv1d_fn.__module__
  → "transformers.models.qwen3_5.modeling_qwen3_5"

Conclusion

Neither package provides a performance benefit on Windows 11 / AMD ROCm. The service runs on the PyTorch reference kernels, which are correct but suboptimal. A future Linux deployment with triton support would unlock FLA's optimized kernels for the 24 DeltaNet layers.

  • Evaluate v2 prompt quality on real video samples to confirm that evidence-bounded wording and the strict taxonomy produce better observations than v1.
